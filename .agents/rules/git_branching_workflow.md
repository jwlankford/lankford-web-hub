# Git Branching & PR Workflow

Ensure all code changes are committed and pushed via a feature branch, and submitted as a GitHub Pull Request.

## Rules

1.  **Do Not Commit to main:** Never commit code changes directly to the `main` branch.
2.  **Use Feature Branches:** Always create and switch to a descriptive feature branch (e.g., `feature/name-of-feature`) before making any edits or commits.
3.  **Submit Pull Requests:** After committing changes to your feature branch, push the branch to GitHub and output the direct URL to open a Pull Request for the user to review.
4.  **Reset Local Workspace:** Switch back to the local `main` branch once the branch is pushed, ensuring your workspace remains clean and aligned with `origin/main`.
